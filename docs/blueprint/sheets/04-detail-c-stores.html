Elasticsearch · settings, mapping and query DSL
settings
number_of_replicas 0 · refresh_interval 5s · elasticsearch client used directly, so web requests, Celery workers and the CLI share one code path
lexical DSL
bool { must: multi_match best_fields, title^3 abstract^2 search_text authors^2 equations^2, minimum_should_match “2<70%” · should: phrase multi_match ×2.0 · filter: facets }
kNN DSL
knn { field: embedding · query_vector · k · num_candidates: max(200, k) · filter: facets, + multi_match “or” over title, abstract, search_text when vectors are hashed }
highlight
search_text, abstract · a kNN hit passes the query text as highlight_query so a semantically retrieved document still shows why it is on screen
facets · related
terms aggregations, best-effort (an aggregation error never blanks results) · related(doc_id): vector neighbours, num_candidates (size + 1) × 10, lexical fallback
Postgres · schema and SQL
schema
psycopg2 plain SQL, no ORM · CREATE EXTENSION vector tried inside a savepoint; without it the embedding column is omitted and only lexical search runs
lexical SQL
WHERE search_vector @@ websearch_to_tsquery('english', q) ORDER BY ts_rank_cd(search_vector, query) × (2.0 if phraseto_tsquery matches, else 1) DESC LIMIT n
semantic SQL
WHERE embedding IS NOT NULL [AND search_vector @@ any-term tsquery, when the vectors are hashed] ORDER BY embedding <=> %(qvec)s::vector LIMIT n
any-term gate
plainto_tsquery('english', q)::text with ' & ' rewritten to ' | ' (regexp_replace), cast back to tsquery · a stop-word-only query matches nothing
highlights · note
ts_headline('english', …, websearch_to_tsquery) · authors stay out of search_vector: array_to_string is STABLE, not IMMUTABLE
