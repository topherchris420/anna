Section B-B · ingestion pipeline and the Document part
Cut through items 5 and 6 (see SHT 01). Twelve source plugins feed one IngestionPipeline; every raw record is normalised into the single Document shape that both stores index and search returns.

ENTRY POINTS
engine_cli “flask engine …” · Celery engine.ingest_source, engine.reindex_all (100 per source) → pipeline.run(source, limit, batch_size = 64)
1 · FETCH
plugin.fetch() · raw records · httpx, pypdf, DocsCrawler · timeout 30 s
2 · NORMALISE
plugin.normalize() → Document · id = source:sha1[:16] · equations, code auto-flagged
3 · BATCH
64 Documents per flush · progress callback per batch · stats.fetched += 1 each
4 · EMBED
encode_batch(embedding_text) · model batch 32, L2-normalised · failure → stats.errors, never aborts
5 · BULK INDEX
backend.bulk_index(batch) → ES bulk (refresh 5 s) | PG upsert · (success, errors) → stats
Part detail · Document · engine/documents.py · one shape for every source and both stores
identity
id · source · kind · title
make_id → “source:” + sha1(source:native_id)[:16] · re-ingest updates, never duplicates
text
abstract · body · equations[]
LaTeX / MathML detected by regex: $…$ or \begin{equation | align | math}
links
url · pdf_url
keyword, index: false · returned, never searched
people · time
authors[] · published · updated · version
dates accept strict_date_optional_time, epoch_millis, yyyy-MM, yyyy · malformed ignored
taxonomy
categories[] · tags[] · language · identifiers{}
keyword facets · identifiers is an enabled object (doi, arxiv id, …)
flags
has_equations · has_code · popularity
has_code forced true for kind ∈ {code, repository} · popularity normalised upstream
vector
embedding[384]
dense_vector cosine, index: true (ES) · vector(384) with <=> (PG) · excluded from _source on read
meta
extra{} · indexed_at
free-form source payload · UTC ISO-8601 stamp at construction
Derived text · what each retriever actually reads
search_text()
title ⏎ authors ⏎ abstract ⏎ body ⏎ categories ⏎ tags → BM25 field search_text (ES) · PG instead builds search_vector from title A, abstract B, body C
embedding_text()
title ⏎ abstract ⏎ body[:2000] → encode_batch → embedding · titles and abstracts carry the signal; the body cap keeps vectors focused and encoding fast
