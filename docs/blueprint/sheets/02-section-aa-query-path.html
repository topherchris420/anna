Section A-A · hybrid query path
Cut through item 3, ENGINE CORE (see SHT 01). engine.search.SearchService.search() and its Postgres twin engine.pg.search run the same section: two retrievers in parallel, one rank-level fusion, one 0–1 relevance scale.
Lexical route · mode ∈ {hybrid, bm25}
Semantic route · mode ∈ {hybrid, semantic}
QUERY q
GET /api/v1/search?q=…&mode=hybrid · engine_api.search() → backend.get_search_service()
LEXICAL · BM25
multi_match best_fields · title^3 · abstract^2 · search_text · authors^2 · equations^2 · minimum_should_match 2<70% · phrase clause ×2.0
RANKING L
ids by _score · size = max(100, page × per_page) · _source excludes embedding · highlights on search_text, abstract
EMBED QUERY
embedder.encode(q) · all-MiniLM-L6-v2 · 384-d · L2-normalised · fallback: md5 token hashing → kNN gated to docs sharing a query term
kNN · COSINE
field embedding · k = max(100, page × per_page) · num_candidates = max(200, k) · filter: facets (+ any-term multi_match when hashing)
both requests are fired concurrently; a model failure never blocks the lexical result, and a retriever that fails is left out of the fusion
RECIPROCAL RANK FUSION
score(d) = Σᵢ wᵢ / (k + rankᵢ(d))
k = rrf_k = 60 · w = 1, 1 · pure function · one ranking only → 1 / rank
EXPLAIN + NORMALISE
explain_rankings → ranks {bm25, knn}, contributions 1/(k+rank) · relevance = score ÷ ceiling · ceiling = n/(k+1) = 2/61 ≈ 0.0328 hybrid, 1.0 single
SEARCHRESULTS → JSON
hits = fused[(page−1)·per_page : +per_page] · facets: best-effort aggregations · total · took · mode label names what ran
WORKBENCH
renderResults(), renderTree() · then POST /api/v1/summarize → SHT 05
