Anna · R.A.I.N. DataMatrix Engine

Open infrastructure for knowledge: a self-hostable, open-source search engine for engineering corpora — research papers, standards, source code and vendor documentation — that answers with source evidence you can inspect, records you can verify and citations you can paste. A Vers3Dynamics project, built on the Elasticsearch + Flask search architecture of Anna's Archive.

How search works

Every query runs two retrievers in parallel: a lexical query (BM25 on Elasticsearch, full-text search on PostgreSQL) and a dense-vector kNN query over locally computed embeddings. Their rankings merge with Reciprocal Rank Fusion, so exact terms and meaning both surface; every hit shows its rank in each list under Why this result?, and relevance is reported on one 0–1 scale across the page, the API and the agent endpoint. Without a sentence-embedding model the vectors come from a deterministic term-hashing fallback, which is not semantic — the engine says so on every page and in /api/v1/health rather than advertising a search it cannot do.

What a report establishes

The source report quotes exact passages with their document, field and offsets. Model prose, when a local model is enabled, is labelled separately and never shown without citations. A saved research record carries a SHA-256 fingerprint and can be re-checked later against the current index — from the workbench, flask engine verify-record or POST /api/v1/evidence/verify. Every document can be cited as BibTeX or plain text, identically from the page, GET /api/v1/document/<id>/citation and flask engine cite.

REST API

Everything these pages do is available as JSON under /api/v1: /search, /document/<id> (with /related and /citation), /summarize, /compare, /evidence/verify, /collections, and /agent/search for LLM tool use. See /api/v1/health for what this instance runs.

Faces of the same engine

These pages are one face; the static research workbench (the frontend/ directory, deployable on any static host) is another, with the same evidence contract, offline Demo Mode and research-record exports. The deck and the blueprint animation explain the pipeline; both are self-contained and work air-gapped, like the engine.

Extending it

Adding a new source is a single file that subclasses SourcePlugin (or the DocsCrawler base) and registers itself with @register. Drop it into engine/ingest/sources/ and it appears everywhere — no wiring required.
